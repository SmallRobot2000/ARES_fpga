# 512x384 conversion validation

The source framebuffer is 512x384 RGB565, scaled 5:4 to the unchanged
640x480 VGA timing. The RTL and software use LG16 (three 128-row strips), one
TMU, depth/stencil/fog/filtering enabled, and mipmapping disabled. Autoload
stays off. The physical reservations are unchanged; the DMA-proxy allocation
is seven 1 MiB buffers per channel.

The external RasterIX ceiling-division change and compile-time tests are
preserved in `patches/0001-correct-strip-ceiling.patch`. The dispatcher already
uses ceiling division for its runtime strip count. Its equal-height strip
handling gives exactly three 128-row strips here; no partial final strip occurs.
Its existing handling of other resolutions whose heights do not divide evenly
by the runtime strip count was not changed by this conversion.

## Local checks

- `python3 linux/rasterix/tests/check-hardware-config.py`
- `sh linux/rasterix/tests/check-triangle-lists.sh` (fresh native CMake build)
- `sh linux/dma-proxy/tests/check-framebuffer-handshake-rtl.sh`
- `sh linux/dma-proxy/tests/check-framebuffer-scaler-rtl.sh`
- `sh linux/dma-proxy/tests/check-display-command-rtl.sh`
- `python3 linux/dma-proxy/tests/check-framebuffer-reservation.py`
- `python3 linux/dma-proxy/tests/check-texture-reservation.py`

The scaler test compares every active pixel against an independent coordinate
pattern through the synchronous line-buffer model. It checks all 512 columns
and 384 rows, exactly four sequential 16-beat bursts per source row, the full
1536-burst frame count, address bounds, no traffic before a valid framebuffer,
and immediate/VSync handshakes. AXI stalls include a burst held across VSync
a new immediate swap coinciding with replacement-line completion, and a
VSync request arriving exactly at the vertical-blank boundary. The
displayed complete buffer must never be overwritten during a refill.

The native capture validates 15 lists for setup, three frames, and teardown,
128-row strip resolution, 18 Y-offset writes, full 65536-pixel strip operations,
and four full-frame `0x23000094` swaps (including teardown). Compile-time tests
cover one strip, six exact strips, and a partial seventh strip.

The LG16 change does not alter the physical framebuffer size, addresses, or
reserved-memory layout, so the validated LG15 device tree remains compatible.

## Hardware checks (user performs these)

After programming the matching image and booting the rebuilt device tree:

```sh
chmod +x /root/proxy-smoke /root/ares-gl-triangle /root/ares-gl-animate
grep -E '97800000|97c00000|97e00000|97f00000' /proc/iomem
grep xilinx-dma /proc/interrupts
/root/proxy-smoke --display
/root/ares-gl-triangle
/root/ares-gl-animate --frames 300
grep xilinx-dma /proc/interrupts
dmesg | tail -60
```

Check full-screen bars and the one-source-pixel grid for the 0,0,1,2,3,4,4,...
repeat cadence on both axes. During animation, exercise CompactFlash and
Ethernet and check for DMA errors or stalls. Visual scaling, stable swaps,
and CF/Ethernet regression checks remain hardware acceptance criteria.
